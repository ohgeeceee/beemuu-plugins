# beemuu-plugins

The official plugin marketplace for [Beemuu](https://github.com/ohgeeceee/beemuu) —
the open-source BMW diagnostics tool.

**Browse the marketplace:** https://plugins.beemuu.com/

## The site

`plugins.beemuu.com` is published by [`.github/workflows/site.yml`](.github/workflows/site.yml),
which runs on every push to `main`, every 10 minutes, and on demand. It:

1. stamps the current BeeEmUu release into `app-release.json` and the header
   band of `index.html`, using `tools/sync_app_release.py`;
2. validates the manifests (`tools/validate.py`);
3. builds and checks the published artifact (`tools/build_site.py`,
   `tools/test_site_build.py`);
4. deploys it to Pages.

Pages here is a **workflow build**, so a push on its own publishes nothing —
the site only changes when that workflow runs. Keeping the registry current
means keeping that workflow green.

The site states which app release it belongs to, in the header band and in
`app-release.json` (public API):

```json
{
  "schemaVersion": 1,
  "app": "ohgeeceee/beemuu",
  "tag": "v3.7.0",
  "version": "3.7.0",
  "releasedAt": "2026-10-15T04:03:47Z",
  "releaseUrl": "https://github.com/ohgeeceee/beemuu/releases/tag/v3.7.0"
}
```

The band is baked at deploy time and then corrected in the browser: the page
reads `app-release.json` **and** GitHub's latest-release API, and shows the
newer of the two. So a release posted between deploys is visible on the very
next page load, while the deployed files (the registry, the checksums the app
verifies) catch up on the next sync — at most ten minutes behind.

To refresh it locally:

```
python3 tools/sync_app_release.py            # report only (exit 1 if stale)
python3 tools/sync_app_release.py --write    # stamp the latest release
```

## What is this?

A community registry of Beemuu plugins. Anyone can:

- **Download** plugins made by the Beemuu team and the community
- **Submit** their own plugin via a pull request

## Submit a plugin

1. Fork this repo.
2. Copy `plugins/_template.json` to `plugins/<your-plugin-id>.json` and fill it in.
3. Host your plugin package (zip/tarball) somewhere durable — a GitHub Release
   on your own repo works great — and put the download URL + SHA-256 in the manifest.
4. Run the validator locally: `python3 tools/validate.py`
5. Open a PR. CI re-checks your manifest; a maintainer merges; your plugin
   appears on the marketplace site automatically.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full rules (naming, safety
review for anything that writes to an ECU, versioning).

## Plugin manifest format

Each plugin is one JSON file in `plugins/` (community) or `official/` (made by
the Beemuu team). The combined registry served to the app and the website is
`registry.json`, generated by CI — **do not edit it by hand**.

```json
{
  "id": "dtc-report-pdf",
  "name": "DTC Report PDF",
  "version": "1.0.0",
  "author": "ohgeeceee",
  "official": true,
  "description": "Export a full diagnostic trouble code scan as a shareable PDF report.",
  "category": "reporting",
  "tags": ["dtc", "pdf", "export"],
  "homepage": "https://github.com/ohgeeceee/beemuu-plugin-dtc-report-pdf",
  "download": {
    "url": "https://github.com/ohgeeceee/beemuu-plugin-dtc-report-pdf/releases/download/v1.0.0/dtc-report-pdf-1.0.0.zip",
    "sha256": "<64 hex chars>",
    "sizeBytes": 0
  },
  "minAppVersion": "2.2.0",
  "license": "GPL-3.0-only",
  "capabilities": ["read-dtc"]
}
```

Categories: `diagnostics`, `coding`, `reporting`, `data`, `ui`, `tools`.

## Registry API

`registry.json` is served statically and can be consumed by the Beemuu app:

```
GET https://plugins.beemuu.com/registry.json
```
